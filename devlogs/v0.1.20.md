# v0.1.20 dev log

Released 23 November 2026. Previous version: v0.1.19.

## Summary

- Scrolling no longer drops to 30 fps when new content scrolls into view.
- Every nested scroll area (rows, chips, lists, panels) glides with the same
  Lenis easing as the page.
- Filter bars stay pinned and jump back to the first row of results when a
  filter changes.
- The Anime page no longer opens scrolled down.
- Trending page redesigned; rank numbers restyled app-wide.
- Gradient headings no longer clip descenders.
- macOS updates install without Squirrel.Mac (the build is unsigned).

## Changes

### 1. Scroll performance

**Problem.** Scrolling felt laggy on every page. Frame timing with a
`requestAnimationFrame` meter, real wheel input, dev build, 60 Hz display,
1600×900:

| Scenario | Median frame | Notes |
| :--- | :--- | :--- |
| Idle | 16.7 ms | baseline |
| Home, first pass down (before) | 33.3 ms | 30 fps throughout |
| Home, second pass, same load (before) | 16.7 ms | p90 33 ms |
| Home, first pass, reveals disabled | 16.7 ms | p90 17 ms |

The second-pass result showed the cost was in content entering the viewport
for the first time, not in scrolling itself. Disabling the reveal animations
removed it.

**Cause 1: per-card reveal animations.** Rows used framer-motion
`whileInView` on every card (`RevealGroup` / `RevealItem`), animating `y` and
`scale`. framer drives independent transforms from JavaScript, and each
animating card was promoted to its own GPU layer. A row of 20 cards entering
the viewport meant 20 layers created and rasterised at once.

**Fix.** `src/components/ui/Reveal.tsx` rewritten without framer-motion:
- One shared `IntersectionObserver` adds `.is-revealed`. The motion is a CSS
  transition in `globals.css` (`[data-reveal]`, `[data-reveal-group]`), so it
  runs on the compositor.
- `RevealGroup` now reveals the whole row as one element. The per-card
  stagger is gone. `RevealItem` is kept as a plain wrapper for layout.
- Hidden states use 2D `translateY` only, so waiting elements do not get
  layers.
- Grid cards (`MovieCard` with `fullWidth`) use `useReveal` with
  `data-reveal="card"`. Measured at 60 fps on the Movies grid's first pass
  (1 frame over 20 ms out of 63).

After: home first pass, median 16.7 ms, 13 of 73 frames over 20 ms (each
row's single layer being rasterised once).

**Cause 2: resting 3D transforms.** `MovieCard.module.css` had
`transform: rotateX(var(--tilt-x)) rotateY(var(--tilt-y))` and
`transform-style: preserve-3d` on every card at rest. A 3D transform, even
`rotateX(0deg)`, is a compositing reason, so every card was a layer.
`BrandTile.module.css` had the same. **Fix:** `transform: none` at rest; the
tilt (now with `perspective()` in the transform) applies only on `:hover`.

**Cause 3: the aurora background.** `.aurora` (fixed, three large radial
gradients) was repainted behind the content on scroll. **Fix:** the drift
animation was removed and `.aurora` got `will-change: transform;
transform: translateZ(0); contain: strict`, so it is rasterised once on its
own layer. Experiment: with the aurora hidden, second-pass p90 went from
33 ms to 16.8 ms; with it as a layer, p90 16.8 ms and max 33 ms.

**Smaller fixes.**
- `ContentGrid.tsx` keyed cards with `` `${item.id}-${Math.random()}` ``, so
  every card remounted (and every poster re-decoded) on each render. Now keyed
  by `item.id`, and appended pages are de-duplicated.
- `backdrop-filter` removed from the small `Countdown` badge and
  `MediaProgressBar` (they sit on cards that move).
- `scroll-behavior: smooth` removed from the row CSS modules; it fights Lenis
  setting the scroll position every frame.

**Not changed, worth knowing.** The home hero's `Glass` buttons use SVG
backdrop-filter refraction over a parallax backdrop and are re-filtered every
frame while the hero is on screen. They are small, so they were left alone.

### 2. Smooth scrolling for nested scroll areas

**Before.** Only the page used Lenis. Nested areas opted out with
`data-lenis-prevent` and scrolled natively (stepped wheel scrolling), and
`ChipRail` turned vertical wheel into an unsmoothed `scrollBy`.

**How it works now** (`src/components/ui/SmoothScroll.tsx`):
- Any element marked `data-smooth` gets its own Lenis instance
  (`wrapper` = `content` = `eventsTarget` = the element, `naiveDimensions:
  true` so sizes are read live as rows load):
  - `y`: vertical lists (episode lists, search palette list, description
    modal body, sidebar nav).
  - `x`: rails. `gestureOrientation: 'horizontal'`, so only sideways
    gestures and Shift+wheel move them; the plain wheel still scrolls the page.
  - `chips`: filter chip strips. `gestureOrientation: 'both'`, so the plain
    wheel scrolls them sideways.
- A `virtualScroll` callback returns `false` when the element has nothing to
  scroll, so the wheel falls through to the page.
- A `MutationObserver` on `<body>` attaches instances to elements as they
  mount and destroys them when they leave the DOM.
- One shared `requestAnimationFrame` loop drives the page instance and every
  nested one (previously `autoRaf` on the page). Lenis eases by elapsed time,
  so the feel is the same at 60, 120 or 144 Hz.
- `getSmoothScroller(el)` exposes an element's instance: `Rail` uses it for
  the arrow buttons, `ChipRail` for centring the selected chip.

Verified: a sideways scroll on a home row ran at 60 fps (4 of 335 frames over
20 ms) and the page did not move. A vertical wheel over the same row scrolled
the page. The search palette list scrolled to its end while the page stayed
still.

### 3. Anime page opening scrolled down

**Cause.** `ChipRail` called `scrollIntoView({ block: 'nearest' })` on the
selected chip on mount. `scrollIntoView` scrolls every scrollable ancestor,
including the page, so it pulled the window down to the filter bar.

**Fix.** `ChipRail` skips the first render and, on later changes, computes
the chip's `offsetLeft` and scrolls only the strip (through its Lenis
instance). Verified: `scrollY` is 0 after the Anime page loads.

### 4. Pinned filter bars that jump back to the results

New `src/components/ui/FilterDock.tsx`:
- `FilterDock` renders a zero-height anchor `div` and a sticky container
  (`top: calc(var(--titlebar-height) + 10px)`, `z-40`).
- `useFilterDock()` returns `toResults()`, which calls `scrollToResults()` in
  `SmoothScroll.tsx`: target = anchor's document top minus the dock's sticky
  `top`. It glides there (0.6 s) only if the page is below that point.

Used by `DiscoverFilters` (Movies, Series), `AnimePageClient` and the studios
and streaming page, which already had a sticky bar but never scrolled back.
Every filter handler calls `toResults()`. Verified on Anime: from 1,800 px into
the results, choosing a genre landed at the target within 1 px, with the bar
at the top and the first card row directly under it.

### 5. Trending page redesign

`src/app/trending/TrendingClient.tsx` and new `Trending.module.css`, with no
framer-motion:
- **No. 1:** full-width banner with a w1280 backdrop, overview, Play and
  More info.
- **Nos. 2 to 4:** 16:10 artwork cards with large rank numbers.
- **No. 5 onwards:** a two-column chart (one column under 1180 px) with a
  16:9 thumbnail, meta and a movement badge.
- **Movement:** this week's chart is fetched in the background. On the Today
  view, each title's rank is compared with its rank in this week's chart under
  the same Movies / Series filter. The badge shows up, down, same, or "New"
  when the title is not in the weekly chart.
- Zero ratings (unreleased titles) are hidden instead of showing "0.0".
- Switching view replays a CSS entrance (`key` on the view container).

### 6. Rank numbers

Shared by `TopTenRow.module.css` and `Trending.module.css`:
- **Font.** `Archivo Black` (via `next/font/google` in `app/layout.tsx`,
  variable `--font-rank`, weight 400; it has a single weight, so 900 would
  trigger faux bold).
- **Why not Outfit.** Outfit is a variable font whose heavy glyphs are built
  from overlapping contours, and `-webkit-text-stroke` traces those overlaps
  inside the digits (the 4's crossbar through its stem, a notch in the 8).
  Google's static 900 cut keeps the overlaps too, so it was tried and dropped.
- **Why the old CSS looked thin.** It asked for `'Satoshi'`, which the app
  never loaded, so the numbers fell back to a system font.
- **Hover.** Sand stroke, 16% Sand fill and a Sand glow (previously the
  green primary colour).

### 7. Clipped descenders in gradient headings

`background-clip: text` paints only inside the element's box. In
`PageHeader` the title `<span class="text-gradient">` is a flex item, so it
is blockified with `line-height: 1`, and its box ends above the tails of
g, j, p, q and y. **Fix** in `globals.css`, inside `@layer components` so
spacing utilities such as `mb-6` still win: `.text-gradient` and
`.bg-clip-text` get `padding-bottom: 0.16em; margin-bottom: -0.16em` (and a
little right padding, offset the same way), plus `box-decoration-break:
clone`.

Verified with a DOM scan comparing each text node's range rect with its
clipping box on Home, Trending, Anime, Movies, details, person, Settings and
Watchlist: no clipped text. The scan was first checked against a synthetic
clipped "Trending".

### 8. macOS updater without Squirrel.Mac

**Cause.** The macOS build is unsigned (`CSC_IDENTITY_AUTO_DISCOVERY: false`
in `.github/workflows/build.yml`). With `autoInstallOnAppQuit = false`,
electron-updater's `MacUpdater.quitAndInstall()` asks Squirrel.Mac to fetch
the update from its local proxy and waits for Squirrel's `update-downloaded`
event. Squirrel rejects unsigned apps, so the event never fires and the app
sat on "Restarting to update".

**Fix.** New `main/mac-install.js`, called from `quit-and-install` on darwin
in `main/updater.js`:
1. The app bundle is found from `app.getPath('exe')`. Installs are refused,
   with a message, when FlixView runs from `/Volumes/` or an `AppTranslocation`
   path, or when its folder is not writable.
2. The downloaded zip (`info.downloadedFile` from `update-downloaded`) is
   unpacked with `ditto -x -k` into a `flixview-update-*` temp folder.
3. A small bash script, started detached, waits for the app's PID to exit,
   moves the old bundle to `FlixView.app.previous`, copies the new one in with
   `ditto` (restoring the old one if that fails), clears the quarantine flag,
   reopens the app and removes the temp folder. Every path argument is
   checked against an expected pattern before anything is moved.
4. The app quits, with `app.exit(0)` as a fallback after 4 seconds.

`UpdateContext.tsx` now shows errors that arrive in the `downloaded` state,
and `UpdateModal.tsx` says "The update did not finish" instead of blaming
the download.

**Important.** Users on v0.1.19 still run the old updater, so their update to
v0.1.20 will hang once. The release notes tell Mac users to install v0.1.20
by hand. If the app is ever signed and notarised, `quitAndInstall()` works
again and `mac-install.js` can be removed.

## Website (website/)

Not versioned with the app, but changed in this cycle:
- Footer wordmark: letters no longer clipped on the right (per-letter
  padding with a matching negative margin).
- "Ads stay out" tile: the "0" was clipped; it now has no negative tracking
  and has right padding.
- How it works: step numbers use Archivo Black, self-hosted in
  `website/fonts/` because the CSP only allows `font-src 'self'`. The active
  step lights up like a hovered rank in the app.
- Scroll progress bar: it tracked correctly but was nearly invisible (2 px,
  dark teal start). Now 3 px, mint to Sand, with a glow and a faint track.
- Ticker: always moves left, and speeds up while scrolling in either
  direction (it used to reverse when scrolling up).
- Download fallback links updated to v0.1.20.
